## Code (ps5-porter porter/elements)
- `APS5_STORING_TEMPLATES` (runtime switch): a draw build that stores through BDA is an address-table template used
  one at a time (noteReusable: templated without bdaReadOnly; sharedUses stays false; NeverReusable no longer refuses
  storing stages), with per-use descriptor sets for changed data words as read-only templates have.
- Per-use fault buffers (same switch): a use of a storing template while an earlier use is in flight takes a pooled
  fault buffer (ShaderResources::TakeUseFault, bound by PrepareDrawBindings through the use's own descriptor set,
  read and cleared by CompleteUse(hold) -> BdaResources::CheckFault(0, buffer)), so repeats inside a frame no longer
  rebuild.
- BDA range index built on a table-cache miss only (BdaResources.cpp; a hit takes tableBytes from the entry).
- Dispatch miss items prepare on the preparer thread (PrepareSlot, like draws; APS5_NO_MISS_ITEM_PREPARE=1 off).

  (base) -> 2099 ms in pf1 (storing templates on): the committer savings moved into the cross-queue waits.
- Async queues per 10 s (pf1 [packets]): q30 WAIT_REG_MEM 5563 ms, DMA_DATA x76 1658 ms (22 ms each: a GPU wait on the
  source then the copy; hook waits 341 ms), dispatches 946 + indirect 541; q38 WAIT_REG_MEM 5456, DISPATCH_DIRECT x2037
  2182 ms (hook waits 1208 ms); q20 WAIT 3937, DISPATCH x7059 2689 ms (hook waits 1531 ms on dispatch-cache validation).
- The hook waits are CPU reads of GPU-written memory in the capture/validation ([validate]: 65 synced compares per 10 s
  waiting 1618 ms: "larger range" 47, "evidence short" 18; the waited dwords mostly changed (542 vs 68 unchanged), i.e.
  real producer/consumer values between consecutive dispatches that the SRT walk bakes into the shader). Removing them
  needs the recompiler to load such words at run time instead of specializing on them.
- Conclusion: after the committer work the frame is a CPU<->GPU dependency chain across queues (q0 draws -> GPU -> q30/q38
  compute -> GPU -> q0 waits), with CPU recording and capture waits in every hop. 3 fps needs (a) the capture waits gone
  (runtime loads for GPU-written words), (b) DMA_DATA on q30 recorded on the GPU without the source wait, (c) cheaper
  async-queue dispatch packets (q38 ~1 ms each), and still the GPU chain itself (~280 ms busy per frame).
- Experiments not worth repeating: APS5_DRAW_PIPELINE, adaptive or 4096 resource cache, dispatch miss items (+preparer).
- Worth keeping: APS5_STORING_TEMPLATES (committer -26 %, no faults), deferred stores (+4-5 %), item depth-plane clears.
